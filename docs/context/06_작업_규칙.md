# 작업 규칙

## 협업 방식
- **Claude는 연구를 대신하지 않는다.** Woncheol이 순서대로 직접 진행하고, Claude는 단계별로 조언하고 과정을 점검한다(2026-10-21). 단, Woncheol이 분석을 직접 요청하면 실행한다.
- 계획은 작업 가설로 취급한다. 약한 가정은 짚고, 선택지와 추천을 함께 주되 결정은 Woncheol이 한다.
- 각 분석이 무엇을 확인하는지 설명하고, 용어는 처음 쓸 때 정의한다. 표와 예시를 쓰고 출처를 단다.
- Woncheol의 배경: 통계는 기초, 회귀는 이론까지 공부함, Transformer·CNN은 자주 사용, 강화학습은 기본 개념만. 통계와 강화학습은 깊게, 신경망 설명은 짧게.
- 체스 기보를 직접 읽기 어려우므로, 판을 눈으로 확인해야 할 때는 Claude가 판을 그려서 판단한다.

## Codex 지시문 형식 (2026-10-23)
- 순서: 배경 → 목표(정확한 출력 파일과 열) → 절대 규칙 → `summary.md` 검수 기준 → 참고 방법
- 목표와 절대 규칙만 확정한다. 방법은 참고로 두고, Codex가 바꾸면 무엇을 왜 바꿨는지 기록하게 한다.
- 시간 제한은 두지 않는다.
- 예시: [docs/codex/codex-task-lichess-all-games-meta.md](../codex/codex-task-lichess-all-games-meta.md)

## 보안과 데이터 규칙
- **Lichess 토큰은 비밀이다.** 환경 변수 `LICHESS_TOKEN`으로만 쓰고, 채팅, 코드, 로그, 매니페스트, 커밋 어디에도 남기지 않는다.
- Lichess 요청은 한 번에 하나씩 보낸다.
- PC의 `data/` 아래 기존 파일은 수정하거나 지우지 않는다.
- 데이터 파일은 커밋하지 않는다. 이용자 이름 목록과 대국 ID가 든 파일도 저장소에 올리지 않는다.
- 클라우드 분석 환경에서는 `database.lichess.org`와 `lichess.org` 접속이 막혀 있었다. 내려받기는 PC에서 Codex가 맡았다.
